## Done

- **New fields:**
  - `desktopSprite` in `modster.json`: `file`, `frames` 2–8, `fps`.
  - `desktopSprite` in `catcher.json`: `file`, `frames` 1–16, `glowColor`,
    `rimColor`, `lidRows`.
  - `desktopBackground` in `biome.json`: `file`, `frames` 1–4.
  - All are allowed in built-in and user content. The field checks are in
    `check-desktop-ref.ts`.
- **The PNG check:** `plugin/hooks/content/desktop-sheet.ts` checks a desktop
  PNG against decision 0045 and keeps it as base64:
  - byte budget and frame size, checked from the PNG header before decoding;
  - the sheet splits into equal frames;
  - every pixel fully opaque or fully clear;
  - at most 64 opaque colours.

  Limits are in `CONTENT.desktop`.
- **Catchers:** `checkCatcherDesktop` checks beat frames, `glowColor`,
  `rimColor` and `lidRows` against the sheet.
- **Loading:**
  - The loader reads desktop art through a new `ContentReader.readBase64` port.
    `register.tsx` backs it with `$.fs.read(…, { as: 'bytes' })`, which was
    already used for user PNG sheets, so there is no new API call.
  - Bad desktop art is listed and left out; the content still loads with its
    terminal art.
  - Loaded content gets `desktop` (Modsters, catchers) and `desktopBackground`
    (biomes).
- **Docs:** `CONTENT_FORMAT.md` has the new fields and a "Desktop art" section.
- **Tools:**
  - `tools/check-content.mjs` requires a credits row for each built-in desktop
    sheet.
  - `tools/sprite.mjs --desktop modster|background|catcher` checks a sheet and
    writes nothing.
  - The player helper's `check` reader can read desktop art too.
- **Tests:** a new `desktop-sheet.test.ts`, plus cases in the validator and
  loader tests and in `tools/sprite.test.mjs`.
- **Checks run:**
  - `claude plugin test ./plugin`: 901 pass.
  - `pnpm test:tools`: 37 pass.
  - `claude plugin validate ./plugin --strict` and `node tools/check-content.mjs`
    pass.
  - `node tools/check-tracking.mjs` passes.

## Decisions made

- Making the terminal `sprite` optional moved to P5-45 (asked @danielpg95). It
  touches every place `register.tsx` reads a loaded sprite (47), which is the
  fallback work.
- Alpha must be exactly 0 or 255, since the PNG is drawn as-is (asked
  @danielpg95).
- Earlier, @danielpg95 chose to load desktop-only content as is and leave the
  terminal fallbacks to P5-45. That no longer arises, since a terminal sprite
  is still required.
- Not set by 0045, chosen here:
  - a desktop background may be up to 192 px wide per frame (the terminal's 48
    at 4× finer pixels);
  - a desktop catcher has 1–16 frames, as on the terminal.
