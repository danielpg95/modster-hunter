## Done

- **Claim** through PR #106 (`claim/p4-02`), merged before work started.
- **`/modsters reload`** (`plugin/hooks/register.tsx`, `reloadContent`):
  loads content again and replies with what loaded, e.g.
  `Modster Hunter: reloaded · 1 biome, 2 Modsters · 1 problem, see /modsters → 4: Settings`.
  Two reloads at once share one load.
- **Encounter unaffected:** the Modster is pinned when it appears
  (`encounterModster`), so its name and sprite stay; tier, throws and catch rate
  already lived in the encounter. The machine's context is swapped, so only the
  next spawn uses the new content.
- **Dropped biome:** `retiredBiome` keeps the old biome while its encounter
  finishes; `moveToNewBiome` then picks a new one, keeping turn and agent state,
  and toasts `Modster Hunter: now in <biome>`. With no biome left, the machine
  stops until a reload brings one back. `sessionBiome()` replaces the three
  `content.biomes.get(biomeId)` lookups.
- **Pane caches:** a reload calls `loadCollectionRecords`, clears
  `cellsByModster`, `silhouettes` and `biomeScenes`, and drops the collection
  sprite site and the Biomes scene site. `cellsByModster` entries now remember
  the sprite they were made from, so the pinned encounter sprite can't leak its
  old cells into the Collection tab.
- **Settings tab:** `plugin/hooks/render/settings-lines.ts` (`settingsLines`):
  a count (`2 errors, 1 warning`), every issue via `formatIssue` (errors first,
  warnings dim), then `Changed a file? Run /modsters reload.` and the `/config`
  line. Not windowed; the engine scrolls the pane body, like the Stats tab.
- **Placeholders:** the `placeholder` field and entries are gone from
  `plugin/hooks/render/collection-tabs.ts`.
- **User skill:** `plugin/skills/create-modster-content/SKILL.md` now tells
  players to run `/modsters reload` instead of waiting for the next session.
