## Problems and findings

- Corrected: "npm import: No" was too strong. Importing a package by name fails (validator and run time), but a self-contained ESM file imported by relative path, even from `node_modules/`, loads.
- Confirmed: no `DecompressionStream`/`Blob`/`Response`; `import()` makes the module fail to load; the 4 MiB `$.fs.read` limit is enforced with a clear error.
- Measured in the runtime: sprite sheet 1–7 ms, 900×900 noise 259 ms, 2048×2048 812 ms.
- 4-bit palette PNGs (common after oxipng/pngcrush) are rejected with a readable error. Grayscale and interlaced are also unsupported.
- PIL saves any palette of ≤ 16 colors as 4-bit. Small 12×12 Modsters often have ≤ 16 colors, so user PNGs may hit the error more than expected.
- The first palette+tRNS fixture had the wrong transparent index (solid background). Hashes still matched, so decode results stood; rebuilt with index 0 transparent.
