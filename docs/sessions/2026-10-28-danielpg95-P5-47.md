## Done

- **Image-mode check, first:**
  - Drawn as an image, a throw's SMIL motion, filters and sparkles all run in
    the Code tab.
  - But the app restarts an image Svg's animation on every redraw. During a
    throw the band redraws on each dot change, so the opening kept replaying.
  - A negative SMIL `begin` fixed the replay but left a one-frame flash of the
    Modster: an image shows its plain attribute values before SMIL applies.
  - The fix: `catchSvg`'s new `fromMs` option builds a new Svg that starts at
    the current moment, so its plain values are that moment's state.
  - @danielpg95 checked both rounds in the Code tab.
- **`content/desktop-sheet.ts`:** a loaded sheet now also records `bounds` and
  `mainColor`, measured as `catch-frame` measures terminal art. No pixels are
  kept.
- **`render/catch-frame.ts`:** `prepareDesktopCatch` builds a throw's art from
  desktop sheets or terminal sprites, on either side.
  - A sheet plays at a quarter of its pixels per terminal pixel
    (`CATCH.desktopPixels`), so the throw keeps the terminal's geometry and
    motion constants and shows at today's size.
  - `lidRows`, `glowColor` and `rimColor` come from `desktopSprite`.
- **`render/catch-svg.ts`:**
  - Each sheet is embedded once in `<defs>` and reused with `<use>`.
  - Catcher frames and lid rows are nested viewports on the sheet.
  - The Modster steps through its frames at its `fps`.
  - The glow is an exact colour-match filter: per-channel discrete tables,
    summed into a mask, flooded with the Modster's colour.
  - A silhouette filter covers the Catchers preview before any catch.
  - `fromMs` resumes a throw.
- **`register.tsx`:**
  - A throw keeps terminal art (blitted) and desktop art (one Svg) apart.
  - The desktop takes a catcher or Modster with desktop art only, while the
    terminal falls back as in P5-45.
  - Throws with a sheet are drawn as an image and resumed on redraw. Throws
    with terminal art on both sides are unchanged (interactive).
  - The Catchers tab preview on desktop uses desktop sheets, with a gray
    silhouette before any catch.
- **Size check:** the largest allowed throw (a 128×128, 8-frame, 48 KiB

## Problems and findings

- **Image-mode Svgs in the Code tab:**
  - they restart their SMIL on every redraw;
  - they show plain attribute values for a moment first.

  Any image-mode animation that must survive a redraw needs a new Svg built
  from the current moment. This matters for P5-48's moving scenes, if they
  embed a background sheet.
- The `<use>` of an embedded `<image>`, nested `<svg>` viewports, SVG filters
  (`feComponentTransfer`, `feFlood`) and SMIL `x` steps all work in image mode.
